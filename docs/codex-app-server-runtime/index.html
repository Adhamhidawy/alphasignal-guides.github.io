Setup

Four steps. Takes effect on the next session. Check marks persist locally.
4 steps
Step 1
Install Codex CLI (0.130.0+)
The runtime requires the Codex CLI globally. Hermes never bundles it. Confirm the version after install.
shell
npm i -g @openai/codex
codex --version
Step 2
Authenticate Codex against the ChatGPT subscription
Tokens land in ~/.codex/auth.json. Hermes will not share OAuth state with Codex CLI (deliberate, to avoid clobbering each other on refresh), so still run hermes auth login codex separately if you haven't.
shell
codex login
Step 3 · optional
Install Codex plugins
Whatever is installed at runtime-enable time gets auto-migrated into the Hermes session.
shell
codex plugin marketplace add openai-curated
codex plugin install linear github gmail calendar
Step 4
Flip the runtime on inside Hermes
Verifies the Codex CLI install, migrates user MCP servers from ~/.hermes/config.yaml to ~/.codex/config.toml, discovers installed Codex plugins, registers Hermes as an MCP server, and writes default_permissions = ":workspace". Takes effect on the next session.
hermes session
/codex-runtime codex_app_server

Use cases

Five scenarios where the Codex runtime pays off, drawn from the article's recommended workflows.
5 use cases
01 · Refactors

Multi-file refactors and migrations

Codex's structured apply_patch runs sandboxed multi-file diffs. Hermes' /goal Ralph loop keeps the migration on-target across turns, and Checkpoints v2 rolls back failed iterations.

02 · ML pipelines

Debugging flaky ML pipelines

Codex inspects logs, edits training scripts, and reruns commands inside seatbelt or landlock. Hermes' background skill review captures the successful fix as a reusable skill for the next incident.

03 · Environments

Dependency hell on fresh environments

Codex's sandboxed shell installs packages, runs build smoke tests, and resolves CUDA or version conflicts. Hermes' memory remembers which configurations succeeded across projects.

04 · CI sweeps

CI and test repair sweeps

Codex patches failing tests file by file inside the workspace sandbox. Hermes' Kanban dispatches each failure to a worker, with heartbeat, reclaim, and zombie detection from the Tenacity Release handling stalls.

05 · Multi-service

Multi-service integration work

Codex executes against migrated MCP servers and the auto-installed plugins (Linear, GitHub, Gmail, Calendar). The MCP callback brings Hermes' browser automation and vision into the same turn.

Daily commands

The reference for the workflow once the runtime is on. Toggle, approvals, sandbox, the cost-saver, and safe config editing.
5 cards
Toggle

Switch runtimes

Effective on the next session. The current cached agent finishes its turn on the prior runtime, so prompt caches stay valid.

hermes session
/codex-runtime codex_app_server   # enable
/codex-runtime auto               # back to default
/codex-runtime                    # current state
Approvals

Allow once · Allow for this session · Deny

When Codex wants to execute a shell command or apply a patch, Hermes shows its standard Dangerous Command prompt. Session caches similar commands. Deny rejects the command, and Codex continues in read-only mode.

Sandbox

Change the sandbox profile

Three built-in profiles: :read-only, :workspace (Hermes default), and :danger-no-sandbox. Override the default in ~/.codex/config.toml outside Hermes' managed block.

~/.codex/config.toml
default_permissions = ":read-only"
Cost saver

Route auxiliary tasks to a cheaper model

By default, title generation, context compression, vision auto-detect, session search, and the review fork all flow through the ChatGPT subscription. The single highest-value tweak for anyone running long autonomous sessions on Plus.

~/.hermes/config.yaml
auxiliary:
  title_generation:
    provider: openrouter
    model: google/gemini-3-flash-preview
  context_compression:
    provider: openrouter
    model: google/gemini-3-flash-preview
  vision_detect:
    provider: openrouter
    model: google/gemini-3-flash-preview
  session_search:
    provider: openrouter
    model: google/gemini-3-flash-preview
  goal_judge:
    provider: openrouter
    model: google/gemini-3-flash-preview
Config

Edit ~/.codex/config.toml safely

Hermes wraps everything it manages between two marker comments. Content outside the markers is preserved across re-migrations. Content inside gets clobbered on the next toggle. Use the space outside for custom MCP servers, sandbox overrides, model preferences, or user-defined permission profiles in [permissions.<name>] tables.

Current limitations

Five items, drawn from the official docs and the announcement reply threads.
5 limits
01

Four agent-loop tools unavailable

delegate_task, memory, session_search, and todo need running AIAgent context that a stateless MCP callback can't drive. Workflows that depend on subagent spawning or mid-loop memory lookups require switching back to /codex-runtime auto.

Source: Hermes docs · What's NOT available
02

Two separate auth sessions

codex login and hermes auth login codex are independent. Users assuming one covers both will hit auth errors. The split is deliberate, not a bug: Hermes will not share OAuth state with Codex CLI to avoid token-refresh races.

Source: Hermes docs · Limitations
03

ChatGPT rate limits absorb auxiliary tasks

Title generation, context compression, vision auto-detect, session search summarization, and the background self-improvement review fork all flow through the same ChatGPT subscription by default. Plus-tier users on heavy sessions will eat their cap unless they route aux tasks to a cheaper model via auxiliary.title_generation and related config overrides.

Source: Hermes docs · Auxiliary tasks and ChatGPT subscription token cost
04

Performance claims are anecdotal

Teknium's "~5% improvement in GPT coding capabilities" and one community user's "p95 latency cut in half on long-lived sessions" came from reply threads, not benchmarks. No formal eval comparing the default Hermes runtime to the Codex runtime on identical workloads exists at publication.

Source: @Teknium reply thread on the announcement · not independently verified
05

Cron and sub-second cancellation not guaranteed

Cron jobs run through the same code path but are not specifically tested. Mid-stream Ctrl+C is sent via turn/interrupt but will not always land if Codex already flushed the final message. Approval prompts may also fall back to a reason string when fileChange data has not streamed yet.

Source: Hermes docs · Limitations + Workflow features

FAQ

Short answers to the questions a developer would actually search.
5 questions
What is the Codex App-Server Runtime in Hermes Agent?+
An opt-in beta runtime in Hermes Agent 2026.5 that hands openai/* and openai-codex/* turns to OpenAI's Codex CLI app-server. Codex executes the shell, sandboxing, file patches, and native plugins. Hermes wraps the session with memory, slash commands, and the self-improvement loop.
Do I need an OpenAI API key to use Codex inside Hermes?+
No. The runtime uses Codex's OAuth device flow against the ChatGPT subscription (codex login writes tokens to ~/.codex/auth.json). There is no added cost beyond a Plus or Pro plan, though auxiliary tasks like title generation count against the same rate limits unless routed elsewhere.
Which Hermes tools stop working when the Codex runtime is on?+
Four agent-loop tools: delegate_task, memory, session_search, and todo. They require running AIAgent context that a stateless MCP callback can't drive. Switch back to /codex-runtime auto when any of them is needed mid-loop.
How do I enable the Codex App-Server Runtime?+
Install Codex CLI 0.130.0+ (npm i -g @openai/codex), run codex login, then inside a Hermes session run /codex-runtime codex_app_server. The flag takes effect on the next session.
Is the Codex App-Server Runtime stable enough for production work?+
Worth Watching, not Production Ready. The toggle is clean and the critical paths (memory nudges, /goal, Kanban) hold, but the four unavailable tools, the two-auth UX, and the absence of a published benchmark argue for using it on shell-heavy sessions while keeping the default runtime for subagent and memory-driven workflows.
